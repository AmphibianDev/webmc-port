Minecraft in a browser

Pick a version. Real ones run Mojang's jar in a JVM in this page; newer ones are compiled ahead of time by this project's build jobs.

What this launcher does

  • No game files are hosted here. The client jar is fetched from Mojang by your browser, or built from it by a job that runs on GitHub.
  • Real Java rows (1.0 – 1.12.2) run the official jar unmodified in the page, and Fabric mods from mods/ load at play time.
  • Compiled rows (1.20.5 and up) have no JVM at play time, so mods are baked into the client before the compile — the mod-set build job does that.
  • Multiplayer needs a relay. A browser cannot open a raw TCP connection, so the client tunnels through a WebSocket relay node; the relay list and a self-hosting guide are below.

Multiplayer: how the connection actually happens

A browser cannot open a TCP socket, so a typed server address is reached through a gateway (or a relay node, in the compiled client's own words): a small server that takes a WebSocket from your page and dials the address for you. Type mc.example.com in the game's address box, not wss://… — the client adds the scheme. This project's own gateway is gateway/server.js, one file, no dependencies, and it speaks the protocol the 26.3 client already implements.

Already have a single-file client? The 26.3 offline build from GoldHQ works with this gateway as it is - its transport is the protocol our gateway speaks - so one command starts a gateway and serves that client with the gateway already set inside it:

python3 tools/play_local.py                      # newest client in ~/Downloads
python3 tools/play_local.py --server mc.example.com   # and join a server on load

The patch is one script tag and nothing else; removing it gives your file back byte for byte. A published client can carry the same setting, baked in by tools/pack_client.py --gateway.

Stored in this browser only (localStorage), never sent to this site. A gateway you run yourself: node gateway/server.js, then put it behind TLS at wss://your.host/v1/connect. MULTIPLAYER.md has the protocol, the policy switches, the nginx block and what not to do.

  • The compiled client's default node list lives in relay-nodes.json inside the build, and the in-game Relays screen can add your own; the 26.3 client takes a gateway as ?gateway= or in localStorage["eagler26.goldproxy"].
  • To run one yourself: the engine's apps/bridge is the relay (Node), with a systemd unit and nginx configs in the same folder. Two environment variables (GAIUS_RELAY_PUBLIC_URL, GAIUS_ALLOW_PRIVATE_TARGETS=0) and it is serving wss://your-host/tunnel.
  • This launcher never sees your traffic: it opens the client, and the tunnel is between your browser and the relay you chose.
